# Phase 4.4：Dashboard 2.0 成长驾驶舱

首页围绕“我是谁、我要去哪、今天做什么、最近留下了什么”组织。导航不变，不新增数据库、迁移、字段或后端接口。不接入 LLM，不部署。

## 四个区域

1. **我的角色 / 当前方向**：沿用中性角色形象，展示已确认的昵称、成长路线与当前目标。目标描述直接显示原文，不自动生成人设。没有记录时显示真实空状态。
2. **今日使命**：展示服务端确认的完成数量和行动状态，按计划时间显示前 3 项。首页只跳转，不提供开始、完成或撤销操作；行动写入入口还检查当前页面必须为每日使命。
3. **成长路线**：显示最多 3 个根分支，按已有更新时间展示，状态直接使用用户设置。点击进入技能树，不展示评分、等级或百分比。
4. **最近成长**：分别显示最近更新项目与资产，各最多 3 项，按实际更新时间排序。项目跳转复用原有详情；资产从已读取内容打开只读弹窗，编辑仍在成长资产库完成。

桌面采用角色与方向主卡、摘要双栏和成果区；手机采用相同内容顺序的单列布局。暖金光晕、金属表面、玻璃卡片、字体和角色绘图组件沿用现有设计。

## 数据读取关系

| 接口 | 区域 |
| --- | --- |
| `GET /api/genesis/home` | 角色、方向、今日使命 |
| `GET /api/genesis/skills` | 技能分支及手动状态 |
| `GET /api/genesis/dashboard` | 最近项目与资产 |

三路独立发起，某一路响应后立即展示，不等待慢接口。每个请求有 15 秒超时。单区域失败仅标记对应卡片；已读取的数据保留并明确标注为上次结果，首次失败显示读取失败而非“没有数据”。卡片上的重试仅请求该接口。

角色和使命共用 `/home`，该接口失败会同时影响这两个区域，不影响技能和成果。技能接口 404 表示该环境尚未启用，显示明确状态。401 仍执行原有登录要求。

首页初始化只读取以上三个接口。使命管理和人工编辑数据仅在进入对应页面后读取。页面加载、刷新、切换和查看详情不产生数据库写入，也不自动生成成长记录或资产。

## 组件与修改文件

- `public/genesis-dashboard-model.mjs`：纯摘要模型、前 3 项与时间排序。
- `public/genesis-dashboard.js`：驾驶舱展示、区域反馈、重试与只读资产详情。
- `public/genesis-cloud.js`：独立读取、响应校验和超时。
- `public/genesis-home.js`：聚合调度、路由与管理页按需读取。
- `public/genesis-skills.js`：复用同一次技能读取，用户编辑后刷新首页摘要。
- `public/growth.html`、`public/index.html`：首页布局与只读详情。
- `public/css/13-genesis-dashboard.css`：驾驶舱样式与手机顺序。
- `public/sw.js`：缓存版本与新样式网络读取。
- `scripts/build-genesis-cloud.mjs`：补齐静态模块；本地构建不代表部署。
- `test/genesis-dashboard.mjs`、`package.json`：测试与检查入口。
- `README.md`、本文：中文使用和边界说明。

## 验证

`npm run test:genesis-dashboard` 覆盖：真实三接口 100 次读取，全库结构与记录不变；单区域失败、慢请求独立返回、单区域重试、未启用状态、认证失败、无效响应、网络失败；时间排序、最多 3 项、手动状态、不修改输入、内容转义和重复纯渲染。

交付前运行 `npm run check:syntax`、`npm test`、`npm run genesis:cloud:build`，并用独立本地测试环境验证浏览器导航、只读详情、390 像素布局和可控接口故障。测试数据不写入用户数据库或提交 Git。

本次验收：全部 29 个测试脚本、语法检查和本地静态构建通过。真实浏览器中，技能首次失败、角色首次失败、成果读取失败保留旧结果、单技能区域恢复重试均已验证；首页无可见完成按钮或百分比，使命和技能各最多 3 项。手机 390 像素宽度无横向溢出，原有模块入口与只读详情继续可用。仅本地运行，未部署。
