# Genesis AI Phase 4.2.1：每日使命

每日使命（Genesis Quest）延续原 Daily Quest 的任务层次、分类强调、完成印记与整日进度，强调用户正在完成自己的成长使命。它仍是行动状态展示与记录层。

## 界面与复用边界

- 导航、首页卡片和使命页面统一使用“每日使命”；保留 `#quests` 路由及原组件 ID。
- 增加当天日期、使命总览、进行中的使命和剩余预计投入时间。无计划显示空状态；未记录时长明确提示，不猜测投入。
- 卡片显示名称、计划时间、类型、预计投入、当前状态、来源及开始／完成／撤销操作。
- 按有效计划时间排列时间轴；同时间保留计划顺序，未知或无效时间放最后。只改变显示顺序，不修改计划。
- 延续分类强调色、进行中突出、完成印记、进度条与保存确认后的短动画。支持减少动态效果偏好和手机布局。
- 原 Daily Quest 的 `renderQuests`、`checkMissions`、`Game.render` 以及旧音效／奖励模块不接入。完成反馈保留“行动记录完成”，不发放积分，不生成成长资产。
- 已有历史完成记录继续只读，明确标注来源。本阶段不变更历史撤销规则。

## 数据边界

接口、认证、去重、三状态模型及数据库结构不变。页面读取、刷新、路由切换、时间轴排序都不写入。只有明确点击的状态操作沿用原保存接口，匹配服务器确认后才更新状态和播放反馈。离线、超时和无效响应不显示成功，不自动重试。

本次只本地修改与隔离副本验证，不操作远程 D1，不部署，不上传个人记忆。使命标题中的原始语言保持不变。

## 验证方式

运行 `npm run check:syntax`、`npm test` 和 `npm run genesis:cloud:build`。原有完成、撤销、重复请求、100 次 GET、网络及认证失败检查继续执行；客户端新增时间排序、相同时间稳定顺序、未知时长、空状态、文本转义及 100 次纯渲染检查。浏览器另检查时间轴、手机宽度及确认后的状态反馈。

## 本轮实际结果

- 24 项测试套件全部通过，原引擎包含 12,000 个随机周回归；语法检查及云端静态构建通过。
- 独立本地副本实际执行撤销、开始、完成，界面依次显示待开始、进行中、已完成，完成后显示“行动记录完成”。
- 操作前后独立行动键仍为 6，成长记录仍为 7，可复用资产仍为 3；其余表内容及结构与副本初始快照一致。
- 再执行 100 次实际浏览器刷新，全部 12 张表内容和结构与刷新前完整快照一致。
- 手机视口 390px：文档宽度 375px，按钮最小高度 44px；页面无横向溢出。
- 两个原始 SQLite 数据库的 SHA256 与上阶段校验值一致。截图和验证副本仅留本地，未提交到 Git。
- 未部署或操作远程 D1。网络故障与重复响应通过实际客户端控制器回归验证；本轮未另做真实断网设备测试。
