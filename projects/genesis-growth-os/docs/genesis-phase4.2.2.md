# Genesis AI Phase 4.2.2：每日使命管理系统

Quest 是当前成长规则，Quest Run 是某一天真实执行的记录。沿用 Express、SQLite 和单页前端，使命业务独立于旧计划与游戏存档。火焰、铁砧、时间轴和卡片只提供交互反馈；状态保存必须来自用户主动操作。

## 页面使用

“每日使命”内部保留两个区域，不增加导航：

- **今日使命**：按时间排列当天安排，支持开始、完成、撤销，服务器确认后显示反馈。
- **我的使命计划**：管理当前规则，按时间排列。可筛选启用、暂停、已删除或全部，并查看执行历史。

点击“创建使命”，填写名称、描述、身体／学习／创造／生活维度、执行时间、预计投入、重复周期，以及可选目标和项目。重复支持一次、每天、每周；一次安排今天或未来日期，每周选择星期。维度是行动分类，不是能力评分。

卡片与计划行的 `···` 菜单支持编辑、调整时间、修改维度、暂停和删除。软删除保留历史，在已删除列表中可恢复。未执行的新规则立即用于展示；首次执行后，今日卡片保留当时内容，管理列表展示最新规则。下一执行日使用当时有效的最新规则。

“执行历史”或使命行的“历史”按钮打开只读档案，可按日期范围、使命和状态查询，分页查看首次快照、完成时间和来源。已删除使命的历史仍可查询。旧记录缺少的信息显示“未记录”，不会用当前定义补造历史。

暂停中的使命不接受新执行操作。已经完成的当天行动仍显示已完成；已删除使命移出今日列表，但历史保留。没有有效使命时显示空状态，不宣称今日已完成。

## 数据与本地迁移

两张表沿用 `0004_genesis_quests.sql`，新增本地迁移 `migrations/local/0005_genesis_quest_history.sql`：

| 表 | 新增字段 | 用途 |
| --- | --- | --- |
| `genesis_quests` | `description`、`dimension` | 当前使命描述与行动分类 |
| `genesis_quest_runs` | `completed_at` | 服务器确认的完成时间，撤销时清空 |

启动时由 `migrateQuests` 检查实际字段。存在缺失字段时，先用 SQLite 在线备份写入数据库旁的 `backups/genesis-before-quest-history-*.sqlite`，备份成功后才在事务中执行增量迁移。备份失败则停止升级。重复启动或重复调用不会重复添加字段、备份或记录；**不要绕过字段检查直接反复执行 ALTER SQL**。

不重建已有表，不删除数据。已有定义的类型映射为行动维度；旧执行快照完全保留，缺失的完成时间保持 NULL，不推测补填。旧快照标注“历史保存快照（旧记录）”，不能倒推为已遵循新快照规则。

定义状态为 `active / paused / deleted`。API 执行状态为 `pending / in_progress / completed`；为保留已有 SQLite CHECK 与历史数据，内部继续存储 `not_started`，在接口处转换为 `pending`。

每个 `(quest_id,date)` 最多一条执行记录。第一次有效开始或完成时保存：`title`、`description`、`dimension`、`time`、`duration`、`repeat`、`goal_id`、`project_id`、`version`，另保留重复日期和关联名称。撤销、再次完成、修改定义都不替换首次快照。首次撤销一个尚未执行的使命不会创建 Run。

记录保留来源、可信状态、隐私和更新时间。新定义及执行均默认 private；用户自报的完成不当作核验证据。当前日期统一使用 Asia/Shanghai，过去日期不能写入。

## API

浏览器会话认证、同源写保护、字段校验沿用现有服务。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/genesis/quests` | 当前定义、启用列表、今日使命、目标和项目选项 |
| `POST /api/genesis/quests` | 创建独立使命 |
| `PATCH /api/genesis/quests/:id` | 编辑规则、暂停、恢复、软删除，必须带 `revision` |
| `POST /api/genesis/quests/:id/state` | 当天 `start / complete / cancel`，必须带定义和执行版本 |
| `GET /api/genesis/quest-runs` | 历史查询，参数 `from`、`to`、`quest_id`、`status`、`limit`、`offset` |

创建示例（关联值需替换成真实存在的 ID，或留空）：

```json
{
  "title": "学习 AI Agent",
  "description": "围绕长期目标完成一次实践",
  "dimension": "learning",
  "time": "20:00",
  "duration": 30,
  "repeat": "daily",
  "goal_id": null,
  "project_id": null
}
```

执行示例（日期与版本来自最新查询）：

```json
{
  "date": "2026-10-13",
  "action": "start",
  "revision": 1,
  "run_revision": 0
}
```

写请求必须带 `Idempotency-Key`，相同键与请求返回 `deduplicated:true`，同键不同内容或版本冲突返回409。参数无效返回400，未登录返回401，跨站写入返回403。客户端失败保留输入，不自动重试、不伪称完成；手动重试同一请求复用请求标识。

历史分页默认20条，最多100条。只查询已有执行事实，不为未执行使命创建记录。兼容旧客户端的 `type`、状态字段和排序接口保留，当前 UI 统一按时间展示，不读取或转换旧 Forge 计划。

## 隔离与运行范围

`GENESIS_ENABLE_QUEST_BUILDER=1` 仅在本地测试环境启用，默认关闭。首页和每日使命只读取独立 Genesis 定义与执行数据，加载、刷新、切换页面都不写入。旧 Forge 存档、引擎、历史奖励表保留但不作为当前行动来源。

数据库、备份、私人验证快照和登录凭据均保存在仓库外。备份包含新使命数据；旧导出协议暂不包含新表，不应使用旧导出代替完整 SQLite 备份。

Cloudflare Worker 尚未提供本阶段使命接口。迁移位于 `migrations/local/`，未操作远程 D1，未部署或同步个人计划。静态云端构建仅验证资源可打包。

- 浏览器独立副本验证真实创建、编辑、开始、完成及历史展示；验收内容不写入用户使用库。

- 全套27项测试包含原引擎12,000个随机周；语法检查和静态云端构建同时验证。
