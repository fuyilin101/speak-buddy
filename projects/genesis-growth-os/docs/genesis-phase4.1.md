# Genesis AI Phase 4.1：个人成长首页与行动卡片

本阶段将入口从项目统计改为个人成长状态，保留 Express 单页架构、The Forge 视觉组件以及 Genesis 资产库。页面加载、刷新与导航仅读取已保存的数据。按用户补充需求，显式点击按钮可记录行动状态，不作为任务验收或奖励执行入口。

## 修改计划与实现

1. 增加成长首页 HTML 和独立样式，原 Forge 页面继续保留在 `/index.html#today`。
2. 增加经身份认证的 `GET /api/genesis/home`，本地 SQLite 与测试 Worker 共用纯展示模型。
3. 复用等级球、XP 条、任务与属性视觉；不加载 `game.js`、`modules.js`、`app.js`，不调用 `Game.render`。
4. 复用既有项目详情、发展时间线、复盘和资产渲染函数；项目数量、成长记录数量与平均进度移入成长资产库。
5. 在临时数据库和实际测试库副本中检查只读行为，再运行原有回归。

## 数据可信边界

- 角色昵称、路线、当前阶段来自明确允许的个人档案字段，只展示用户陈述或已验证的数据。本地可使用已经保存的 Forge 昵称。
- 不把目标名称推断为当前阶段。缺少角色资料时显示“尚未设置昵称”“尚未确认当前阶段”。
- 本地任务和 XP 来源明确标为“本地 Forge”，未同步云端；只有保存过的训练记录有 XP 时才显示原有训练等级。
- 今日 XP 尚无可靠独立字段，因此显示“尚未接入”；不使用任务潜在奖励估算。
- 云端训练尚未连接，等级、XP、任务和连续记录保持空状态。不会请求用户电脑的 localhost 取得训练数据。
- 能力积累按保存的项目领域统计关联项目、成长记录、资产与去重的来源引用，不评价技能等级。“引用数”不等于独立核验通过数。
- 历史 `ai`、`ai_app`、`ai-product` 在展示时归为 AI 应用开发，原始记录不变。实践时长仅使用明确以小时记录的实践项。
- 任务使用独立行动卡片，只有显式完成或撤销按钮执行状态保存；刷新与导航均不执行完成、奖励、连续记录或保存操作。
- 页面不会自动翻译、改写已保存的任务标题或资产内容；新增界面与提示为中文。
- 旧 Forge 离线缓存不接管新首页和它的独立脚本，避免把成长页当成游戏离线入口。

## 启动与部署状态

本地正常启动后 `/` 打开成长首页，`/index.html#today` 打开原有训练系统。进入旧训练系统仍沿用其原有奖励与写入规则，成长首页的自动读取不执行旧奖励逻辑，手动行动状态使用独立存储。

本次截图来自测试数据库的隔离副本。数据库、私有资料、临时凭据和截图均不提交 Git。

本阶段没有新增迁移，没有修改原始本地数据库，没有读取或操作远程 D1，没有上传个人记忆，没有连接 GitHub MCP，也没有实现 Phase 4.2 奖励验收系统。

Worker 仅完成本地 dry-run；没有远程部署。现有 Cloudflare 测试站点仍为先前版本。后续仅在明确授权时部署测试 Worker，再独立验证远程页面与认证；不得将本地通过视为远程通过。

## 补充需求：任务卡片与手动行动记录

按用户确认的 Phase 4.1 补充范围，恢复任务卡片、进度条、轻量完成印记与反馈动画。每张卡片展示原任务标题、安排时间、类型、预计时长、当前状态、来源和操作按钮。首页最多展示三张卡片，每日任务入口展示完整当天列表；手机宽度使用单列，尊重减少动态效果偏好。

- `public/genesis-actions.js`：独立卡片渲染及显式完成/撤销事件。只有服务器明确确认匹配任务、日期和完成状态后才更新进度及触发动画；保存期间禁用重复提交和刷新。20 秒超时、断网、401、无效响应均提示失败或结果待确认，不伪称保存成功。
- `public/genesis-action-model.mjs`：合并两种来源并重新计算行动数量、百分比与剩余时长。原 Forge 已完成状态始终优先且不可从成长页撤销。
- `public/css/09-genesis-actions.css`：分类强调色、完成印记、脉冲与微光、响应式卡片和减少动态效果支持。
- `POST /api/genesis/action-status`：沿用登录会话与 `PUBLIC_ORIGIN` 来源保护，只接受当天已有任务及布尔状态。事务只写既有 `settings` 表的 `genesis_action_states` 键，不修改 `app_settings`、`weeks`、奖励账本、个人记忆或 Genesis 成长记录。
- 每条手动状态保留日期、任务 ID、更新时间、`source_type: manual_action`、`confidence: user_stated`、`visibility: private`。界面显示“自我报告，未验收”。重复保存相同状态返回 `deduplicated: true` 且不更新时间。最多保留 5,000 条，不自动清理。
- 该交互仅在本地 Express 环境启用。Cloudflare 尚无 Forge 任务来源及行动写入端点，保持空状态；不会用本地任务伪装云端成长。原 Forge 导出备份仍按原范围工作，暂不包含独立行动状态，行动数据目前保存在本地 SQLite。

补充验证：`npm run test:genesis-home` 覆盖 Worker 100 次 GET、Express 保存前与保存后各 100 次 GET、手动完成/撤销/重复提交、401、非法来源、配置的代理来源、参数校验、日期与任务匹配、原 Forge 后续完成优先。所有自动读取前后数据库结构及内容一致，手动操作只改变独立行动键。`npm run test:genesis-actions` 执行实际事件处理，覆盖成功确认、未确认不更新、保存和读取互斥、断网、401、无效 JSON、不完整及错配响应、超时、云端禁止写入。原有 20 项回归、语法、Worker 测试、构建及 Wrangler dry-run 通过。

浏览器完成及撤销在隔离副本执行。用户在预览期间进入旧 Forge 手动勾选任务，副本按旧逻辑产生了训练数据；新版成长页测试以返回后的存档重新建立基线。新版卡片的后续操作不改旧存档，100 次实际浏览器刷新后所有 12 张表保持一致、行动状态保留且 XP 展示不变。原始两个本地数据库 SHA256 与本阶段开始时一致。390 像素响应式检查通过，仅为浏览器检查，不等同于真机验收。

本次无新增迁移、远程 D1 操作或部署。独立行动的证据验收、XP 发放及云端存储属于后续范围。
